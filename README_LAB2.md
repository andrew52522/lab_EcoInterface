# Лабораторная работа № 2 — включение и агрегирование компонентов ACOM

Проект расширяет `Eco.MaxMin` из лабораторной №1 интерфейсами `IEcoCalculatorX` и `IEcoCalculatorY`.
Внешний компонент хранит ссылки на внутренние компоненты и делегирует арифметические вызовы.
Варианты компоновки: `A`, `C`, `D`; `E` предоставляет интерфейс `Y` и агрегирует `B`.
Компонент `D` включает `B` для интерфейса `X`, а `E` агрегирует `B`.

**Причина трёх вариантов:** в исходных материалах `Eco.CalculatorA` и `Eco.CalculatorC` имеют одинаковый CID и имя статической фабрики. Они не могут одновременно зарегистрироваться как разные компоненты. Поэтому мы компилируем отдельные варианты с A или C.

## Сборка macOS Apple Silicon

Клонируйте `peerf-eco/Eco.Education` рядом с этой папкой; установите Eco.Framework и Apple Command Line Tools.

```bash
export ECO_FRAMEWORK="/абсолютный/путь/к/Eco.Framework"
make -C AssemblyFiles/Mac/clang_arm64 clean
make -C AssemblyFiles/Mac/clang_arm64 test
```

Команда `test` последовательно собирает и тестирует варианты A, C и D. В них проверяются Max/Min, сложение, вычитание, умножение, деление, переходы через `QueryInterface`, а также обращения к D и E. Тесты возвращают ненулевой код при ошибке. Макрос `ERR_ECO_SUCCESES` обеспечивает совместимость со старыми исходниками преподавателя, не изменяя их.

Сборка запускается Apple Clang в режиме `-std=c89`. Упоминание C89 означает выбранный режим компиляции, а не утверждение, что все файлы Eco.Framework написаны строго на ISO C89 без расширений.
